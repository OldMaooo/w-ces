## 2. 推荐架构：语义顺序与空间路径分开
用户标兴趣点 → 导出规划包 → 外部 Agent 生成参观步骤 → 导入为草案 → 应用计算可走路径 → 用户编辑/检查 → 播放。

Agent 负责语义：选哪些兴趣点、先后顺序、每站目的/停留时长、候选路线名称。应用负责空间：站位、路径、障碍、时间轴、相机、保存。不得让模型直接生成任意代码或将模型声称“可通行”当检查结果。

第一版采用外部 Agent 文件交换，无 API 密钥、模型订阅绑定或本机代理服务。用户可手动新建路线并选择兴趣点，不依赖 Agent 才能使用。未来内置模型只需实现同一规划请求/响应协议，编辑器与播放器不变。本轮不实现内置模型。

本地复用结论：沿用 Three.js、人物、快照/撤销/离线构建；新建少量纯 JS 路线模块，无新增依赖。外部资料搜索 0 次；本计划不依赖未核实的新库 API。

## 3. 创建兴趣点
入口：选中已有物品 → 属性区“设为兴趣点”。一个物品第一版最多一个兴趣点，可取消；取消不删物品。

最少填写：名称（默认物品用途名/物料名）、体验说明（如“体验设备操作”）。高级项折叠：默认停留秒数、默认看向位置、推荐站位/距离。

在场景显示三件不同的东西：物品上兴趣点标记、地面游客站位圆点、两者之间的朝向线。兴趣点是“体验什么”，站位是“人站哪里”，不能把屏幕中心当人脚下坐标。

- 默认看向目标为物品可见表面中心；屏幕优先正面中心，非屏幕使用包围盒中部。允许点击物品表面重新选观察位置。
- 默认站位尝试目标正面外侧（建议距物料边缘 0.8 米），检查越界/碰撞；失败提示拖动站位，不自动放到桌内或展位外。不能从物品名称猜朝向。
- 站位在地面 XZ 平面拖动，观察目标可以在物品表面选点。选中兴趣点不改变物品位置，使用独立拖动手柄。
- 名称/体验说明和站位随展台方案存储；同一兴趣点可被多条路线引用，各路线可覆盖停留时长与站位。
- 物品复制默认不复制兴趣点，避免无意扩大规划目标；复制整个方案则复制全部兴趣点/路线，关联限制在新方案内。

## 4. 创建路线与 Agent 连接
### 4.1 手工创建
“游客路线”面板 → 新建 → 选来向/入口和出口 → 从兴趣点列表添加体验步骤 → 生成连接路径。至少有一个有效体验步骤；允许同一兴趣点多次出现（每次独立 stepId）。无需先写具体剧本。

四个来向使用枚举 north-east-west / north-west-east / west-south-north / west-north-south；只是分类，实际 start/end 独立可拖动，默认从合法开放边界生成。禁止用枚举直接硬编码项目顺序。

### 4.2 外部 Agent 规划闭环
1. 用户点“导出规划资料”：一个 JSON，包含协议版本、requestId、sourcePlanId、场景摘要指纹、坐标定义/单位、场地边界、障碍简化数据、兴趣点（ID/物料ID/名称/说明/世界观察位置/可用站位）、可用来向、用户要求，以及响应格式说明。只导当前方案，不附模型、贴图、其他方案或浏览器数据。
2. 用户把文件给自己的 Agent，要求生成候选路线 JSON。可同时返回若干候选，每条含来向、entryId/exitId（从请求提供的合法端点中选择）、steps:[{poiId,dwellSeconds,note}]。Agent 不输出几何路径，由应用计算。
3. 点“导入路线草案”：文件通过格式/范围/引用校验后先预览候选列表、步骤、路径与问题；点击“加入路线”一次性追加，不替换现有路线。
4. 请求指纹不一致则标“场景已变化”，针对当前场景重新解析 ID、检查站位与寻路，不沿用旧坐标缓存；缺失兴趣点可由用户重选，不按名称自动猜同一物品。不同 sourcePlanId 不自动合并。
5. 相同 requestId+candidateId 重复导入提示已加入，可主动“另存一条”，不静默重复。

JSON 只作数据，说明文本按纯文本呈现；禁止 eval/执行脚本/插入未经转义 HTML。未知字段忽略或报错需在 schema 中固定，第一版采用拒绝未知核心结构字段，用户说明不作为命令执行。

提供 doc 中协议说明和一组可复制的最小请求/响应示例；示例用测试布局，不代表实际路线设计。

## 5. 路线编辑
- 面板显示“路线列表 → 当前路线的体验步骤”。步骤可拖排序、添加/删除、重复、改名称说明、改停留时间；路线可重命名/复制/删除。
- 场景里显示入口、出口、编号站位、连接线和转向；修改站位或入口只拖对应手柄，不移动物料。
- 每段支持插入/拖动/删除手工途经点，绕过特定区域。途经点不是兴趣点，不增加体验阶段；寻路必须经过它，不能优化掉。
- 默认自动站位引用兴趣点的本地锚点；“此路线单独调整”生成世界坐标站位覆盖，只影响当前步骤。明确区分改兴趣点默认值和改本条路线。
- 修改语义步骤/站位/途经点后仅重算受影响相邻段；物料移动可能影响全路线，统一失效检查。重算由短防抖触发，拖动过程仅画预览，松手后落盘/一次撤销。
- 进入编辑先暂停；删除当前播放路线退出预览；切换展台方案销毁预览。合法但尚未检查的路线标“待检查”，不可自动播放。
- 编辑保存持久化的是输入：兴趣点、步骤、手工途经点；生成的折线路径/时间表是可重建缓存，不与用户编辑值混存成双真源。

## 6. 空间路径计算（第一版确定性算法）
范围：静态、小场地、一个模拟游客；不是动态人群系统。用规则算法计算，不让 LLM 判断逐帧碰撞。

1. 构建 XZ 可行走网格，默认网格边长 0.1 米、游客半径 0.3 米作为可配置工程常量。仅覆盖当前展台及入口/出口连接过道，避免扫描整个会场。
2. 收集墙与实体物料在游客身体高度内的足迹并膨胀游客半径。地面/路线标记/悬空且高于头部的吊楣不是障碍。圆桌用圆、L 台用两个矩形、长方物料用旋转矩形；其他类型保守包围形状。陈列人物默认作静态障碍，模拟游客自身排除。
3. 8 邻域 A* 连接入口→站位→手工途经点→下一站→出口，禁止对角穿角。每个端点先用几何检查，不将非法点悄悄吸附到另一处。
4. 对结果做视线可通行简化，线段扫掠检查整个游客半径；保留手工途经点。第一版不用可能切穿桌角的样条。
5. 最终每段再次做精确形状碰撞检查；不可达就显示“第 N→N+1 站无通路”，高亮阻挡，不画直线假装成功。
6. 观察视线检查独立于寻路：眼位到看向点的射线被其他物料挡住时给提示；目标自身命中算成功，走得过去不代表看得见。视线遮挡为警告，路径不可达为播放阻塞。
7. 生成任务带 revision；新编辑后旧计算结果不能覆盖新结果。纯计算模块先同步实现并测预算，超预算再放 Worker，不预建异步系统。建议单方案最多100兴趣点、50路线、每条200步骤/每段50手工点，导入总节点和网格最大单元数需硬限制。

网格是近似：很窄通路可能判不可达，先明确提示，不能以放宽游客半径静默解决。0.1米/0.3米为工程起值，不承诺施工或安全通行标准。

## 7. 播放、浏览与确定性时间轴
### 7.1 时间轴
compileRoute(route, resolvedPOIs, pathResult) → move/turn/dwell 段及累计时间；sampleRoute(compiled, t) → position、bodyYaw、baseLook、phase、stepId、animationTime。

- 单一 playhead 秒数驱动位置/相机/游客动画。行走时长=路径长度/走速；停留秒数可编辑；转弯加短 turn 段原地平滑转身，避免身体瞬间反转。总时长显示真实编译结果。
- 播放倍率只改变 playhead 增速；不改路线数据。seek(t) 每次都从时间表采样，不靠逐帧累积倒放，拖回同一时间得到同一结果。
- 滑杆按时间定位；停留时进度增加、脚下不动。按下滑杆暂停，松开仍暂停；阶段标记可点击跳转。重播归零，播放至末尾停在末尾。
- 播放暂停时游客动画也暂停；模型未加载可暂用胶囊标记，资源到位保留当前时间；动画相位与时间表同步。普通陈列人物维持原动画行为。

### 7.2 视角与输入
- 总览：现有 OrbitControls 看路线和临时游客；第一人称：相机放游客脚下+eyeHeight，隐藏自身模型，两视角共享时间/状态。
- 默认眼高沿用现有 1.75 米，路线可改；FOV 沿用现有 65°。不默认改变原自由步行的高度或视野。
- 基础视线：移动看前方、停留看兴趣点；手动鼠标偏移叠加在基础视线上，俯仰限幅。暂停也可转头；“视线归位”清偏移。seek/切路线清偏移，切视角保留当前步骤。
- 第一人称点击画面锁定鼠标；Esc 解锁并暂停，保留位置。拒绝锁定时提供按住拖动转头，不能阻断播放操作。
- 空格只切路线播放/暂停；WASD 在路线模式不移动游客。输入框/中文组合输入不拦截快捷键；窗口失焦或切后台暂停，避免回来跳很远。
- “退出浏览”恢复进入前编辑相机、Orbit target、FOV和选中状态；导入、切方案、删除路线统一调用退出清理。
- 模式统一：editor / freeWalk / routeEdit / routePreview，预览子状态 ready/playing/paused/ended/invalid。只有一个模式拥有相机和键盘，禁止沿用两个 walking 布尔值分支互抢控制。

## 8. 数据模型与变更规则（推荐，待确认）
layout 新增 tour:{schemaVersion:1,pois:[],routes:[]}，全部归属于当前展台方案；编辑器 UI 宽度、当前进度、相机、临时游客不进 tour。

POI：{id,objectId,name,description,lookLocal:[x,y,z],standLocal:[x,y,z],dwellSeconds}。
Route：{id,name,approach,start:[x,z],end:[x,z],eyeHeight,speed,steps:[],connections:[]}。
Step：{id,poiId,dwellSeconds?,standWorldOverride?:[x,z],lookWorldOverride?:[x,y,z],note?}。
Connection：{from:'start'|stepId,to:stepId|'end',via:[[x,z],...]}。

- 坐标米制，Y 向上，地面 XZ；本地锚点以物料根 Group 的 position/rotation 为基准，明确不自动采用 geometry 内部网格缩放；大小改变后标记重新定位。通过显式转换函数维护，禁止把局部值直接当世界值。
- ID：poi/route/step 用 uuid，objectId 沿用当前数字 ID；所有引用按方案作用域解析。步骤排序后保留仍存在的同一对相邻端点连接；失去邻接关系的手工途经点显示将移除提示并随撤销保存，不偷偷套到另一段。
- 移动物品：默认站位和看向点跟随平移/旋转，关联路线标待检查并重新寻路；路线独立站位覆盖不跟随，但目标仍随物品。缩放物料后提示站位复核，避免站位进入物体。
- 物品隐藏/删除、取消兴趣点：不删路线步骤；引用标失效，保留可识别名称用于修复，播放阻塞直到重新绑定/删除步骤。Undo 恢复原 ID/关系。
- 改墙、改场地或移其他障碍：失效所有受影响路径；第一版全体失效重算可接受，小场地先保证正确。
- 复制方案：保留方案内 ID 合法（命名空间由 planId 隔离），深拷贝防串改；跨方案导入路线不按同名对象自动绑定。

### 保存格式迁移
外层 workspace/导出 version 升到3，接受旧2并补空 tour；新 localStorage key 使用 ces-workspace-v3，首次只读旧 v2 迁移，保留原 v2 数据，成功写入/回读后才作为新工作副本。旧工具不支持v3时应报版本错误（当前 parseWorkspace 只接受2），禁止为兼容伪装v2导致静默丢路线。

保留原 workspaceId 和已有多窗口保护，监听新 key；旧版窗口只写 v2，不覆盖新 v3，但两版不实时同步，需要提示已升级使用新版。迁移不可因 tour 校验失败损坏原备份。旧 HTML #seed 仍仅作数据提取。

校验：有限数/数组长度/枚举/唯一ID/有效引用/速度>0/停留≥0/眼高范围/路线总量/说明长度/文件大小；未知新版拒绝导入。缺失对象引用保留为可修复失效状态，而不是静默丢步骤。批量导入在临时对象内校验，失败不修改当前数据。

## 10. 接手执行顺序与验收门
用户将另派 Agent；本聊天不启动子 Agent，不开始实现。

### 第一段：一条真实闭环（先做，其他阶段未开始）
在测试布局中标两个兴趣点 → 手工选顺序 → 自动连接 → 第一人称播放/暂停/拖进度 → 改一处站位 → 刷新恢复。实现必要的模型/最小UI/保存迁移/基础寻路与时间轴，不先填具体业务路线、不做独立一次性假播放器。
门：坐标正确、无穿桌、相机不争抢、拖回同一时刻一致、刷新后兴趣点和路线仍在。启动可用版本由用户验手感，未过不扩充。

## 附：Agent协议最小契约（实施时制作对应fixture）
规划包 format='ces-tour-request',version=1；响应 format='ces-tour-response',version=1。响应必须回传 requestId、sourcePlanId、sceneFingerprint。候选唯一 candidateId；name/summary 为纯文本。第一版 Agent 只选择导出包内 entryId/exitId，不凭空输出起终点坐标；应用将ID解析为候选端点，用户导入后可拖动。第一版固定ID形式，应用负责将端点ID解析为路线start/end坐标，避免Agent臆造坐标。

响应示例（仅展示结构，ID必须来自真实请求；不得直接导入实际方案）：
```json
{"format":"ces-tour-response","version":1,"requestId":"request-example","sourcePlanId":"plan-example","sceneFingerprint":"fingerprint-from-request","candidates":[{"candidateId":"candidate-1","name":"体验路线示例","approach":"north-east-west","entryId":"entry-from-request","exitId":"exit-from-request","steps":[{"poiId":"poi-from-request","dwellSeconds":20,"note":"体验说明"}]}]}
```
sceneFingerprint 覆盖当前room、物料ID/位置/旋转/尺寸/显隐、兴趣点及端点，采用字段排序后的稳定JSON哈希；只用于检测陈旧数据，不作安全签名。请求包同时保留可核验的源摘要，不依赖指纹授权。重复导入记录 candidate 来源元信息于route.source:{requestId,candidateId}，只用于去重提示。

端点导出为[{id,position:[x,z],approach,role:'entry'|'exit'}]，与请求一同冻结；只导出通过边界/障碍检查的端点。未配置合法端点时提示先放置入口/出口，不输出不可完成请求。
