# CES 展台草图方案

## 用途与边界
用于对比展台物品排布的桌面 3D 草图。保留空间关系，不追求施工精度，不做碰撞检测。以现有单页离线编辑器持续修改，不引入账号或云同步。

## 当前交付
- 本地应用 v0.1.18（Figma 贴图）；公开入口仍为 v0.1.13：https://mao-ces-booth-editor.oldmao.chatgpt.site/ 。部署已成功；本机保存、JSON 导出／导入，无云同步。
- 悬浮物品栏、听讲椅、单模型两种角色、人物动画及图层调整均已实现；详细操作与验证见 [使用说明](使用说明.md)。
- 新物品／人物及表面放置定向检查通过；原全量回归仍有墙长互换旋转断言失败。待用户验收拖入手感、人物大小和动画观感。

## 已确认功能（2026-11-13）
- 左侧工具栏更紧凑，保留拖宽；低频微移默认折叠。
- A 为左墙，初始长 5.5 米；B 为后墙，初始长 6.1 米。墙长互换时，靠墙物品保持 A/B 归属与实际尺寸；地面自由物品整体转90°并调整位置。两墙可分别隐藏。
- 指南针北为场地前方（+Z），随观察方向转动。
- WASD 进入人眼高度 1.75 米的游客视图，空格进入/退出，鼠标拖动看方向；退出还原编辑视角。
- 电视支持 48/55/65 寸和自定义英寸，按 16:9 换算。闺蜜机初始 27 寸，白色圆底单杆，可切换横屏/竖屏。圆桌为单根金属腿。
- 物体可立即吸附最近的 A/B 墙，调整屏幕尺寸后保持贴墙；手动旋转解除吸附。每次旋转 45 度，手输角度也按 45 度取整。
- L 型台独立添加，横边长度/宽度、纵边长度/宽度分别可调，台高可调。
- 顶栏左边是方案标签（切换、另存「+」、双击改名、右键复制 / 重命名 / 删除、拖动排序），修改自动存本机。每个方案的布局和撤销独立。顶栏中间「路线 / 展台 / 贴图」是三个互斥的模式。

## 桌面物品与点击放置（2026-11-13）
- 笔记本电脑、电脑摄像头、A4（210×297mm）和 A5（148×210mm）竖版亚克力牌。新建立牌分别添加，旧方案的原立牌保持原尺寸。
- 易拉宝默认画面 80×200cm，含底座整体约 84×208×35cm；可调整整体尺寸。
- 选择物品→点「放置」→点击另一物品朝上的水平表面；底部贴合点击面，保持朝向，自动退出放置。悬停显示落点，Esc 或「取消」退出。侧面不接受放置，圆桌/L台按实际表面命中，不按外接方框计算。
- 放置绕过 0.1m 网格、解除靠墙吸附、支持一次撤销/重做和现有保存/导出。只记录物品位置，不建立依附关系；移动桌子不会自动带走桌上物品。未做越过桌边或物品互相重叠的碰撞检查。

## 悬浮物料栏与人物（2026-11-13，v0.1.13）
- 物品入口在画布顶部悬浮「物品」按钮中，按展台/设备/展示/人物分组；左栏不再显示添加物品。拖入画布水平表面即可创建并贴合，保留点击卡片快捷添加。拖出画布不新增。
- 左侧独立图层管理，底部把手可上下拖高，使用 Lucide Eye/EyeOff 显隐按钮。图层区高度作为本机界面设置保存，不进入方案 JSON。
- 听讲椅为无扶手、四腿的简易会议椅，默认 46×82×50cm；沿用尺寸、位置、旋转、复制、显隐与放置。
- 人物只引入一个 Quaternius Animated Men Pack 的 Man GLB，以工作人员和游客两种默认配置使用：同样的白模材质，工作人员躯干蓝色 #165DFF、袖子仍白；游客默认全白。马甲颜色可改。
- 使用与现有 Three.js 匹配的 GLTFLoader、SkeletonUtils.clone 和每实例 AnimationMixer；动画来自原资产。支持位置、等比缩放、朝向和动画选择；Walk/Run 原地播放，不自动在场地移动。
- 人物数据只有角色类型、等比缩放、动画名和衣服颜色；沿用版本2方案快照、撤销和导入导出。模型及图标内嵌到下载编辑器，离线不依赖 CDN。没有重新建模、行走路径或复杂人群系统。

## 编辑器与方案分离（用户追加确认）
- 编辑器是离线 HTML 工具；「下载编辑器」不携带用户布局。
- 方案是独立 JSON 数据；点「导出」后选「当前方案 / 全部方案」控制导出范围。换编辑器版本只需导入 JSON。
- 方案文件包含版本、活动方案和布局，布局包含房间与物品；侧栏宽度、本机存储标识属于编辑器设置，不写入方案 JSON。
- 旧版下载的 HTML 仍可导入：仅读取其中的 JSON，不执行导入文件中的代码。导入追加为独立方案，不覆盖现有方案。
- 本机自动保存只是工作副本；跨电脑或长期保留用 JSON 文件。多窗口并发修改时阻止旧窗口静默覆盖，提示先导出其独立副本。

## 游客路线功能（2026-11-13，已实现）
- 在独立的平面图纸编辑模式里：物品上标兴趣点（图上显示名称）→ 大方案按来向定入口出口 → 子方案是一串站（兴趣点或路径点）「入口→电视→机器人→出口」→ 程序网格寻路自动绕开障碍物（走不通的段标红并说明被谁挡住）→ 同一块画布底部的播放条：播放 / 暂停 / 拖进度 / 倍速，视角在「平面 / 透视 / 游客」间切换（游客视角可鼠标转头），设置里可「跳过停留」。操作见[使用说明](使用说明.md)。
- 数据存在每个展台方案的 `layout.tour`（兴趣点、大方案、子方案）；路线和时长是算出来的、不存；不升存储版本号。坏的 tour 数据被丢弃并提示，物品不受影响。
- **已知代价**：旧版下载的编辑器打开含路线的新文件会丢路线（不报错）；旧版导出的文件在新版正常打开、无路线。
- 默认方案：浏览器没存过方案时载入 `doc/Files/CES-02.json`（构建时内嵌到 `index.html`），存过则载入上次的；测试用 `?builtin` 回到 3 件物品的旧起点。
- 模块：`src/tour-model.js`（数据）、`tour-path.js`（寻路）、`tour-timeline.js`（时间轴）、`tour-plan.js`（图纸界面）、`tour-player.js`（3D 播放）；入口接在 `src/app.js`。
- 作废：手画路线。
- Agent 批量写路线（2026-11-14）：`node src/tour-agent.cjs list|apply`，Agent 用物品编号/名字写草稿，脚本算站位、用编辑器同一套校验和寻路检查，另存新方案文件，人导入后在界面里改。不改数据格式。格式见[路线草稿-Agent格式](路线草稿-Agent格式.md)；例子 `doc/Files/CES-02-导览路线.json`（5 条）。界面对照样品 doc/mock/route-demo/；技术计划见[计划](plans/2026-11-13-游客路线模拟-计划.md)，派工见[派工 prompt](plans/2026-11-13-游客路线模拟-派工prompt.md)。

## Figma 贴图（2026-11-14，v0.1.19，已合并进 main）
- 需求以 [确认版](plans/2026-11-14-Figma贴图-确认版.md) 为准，界面照可点样品 doc/mock/figma-decal/，但左栏按确认版改成「选面 → 在物体上点面 → 保存 / 取消」。操作见 [使用说明](使用说明.md)。
- **数据**：物体 `userData.decalFaces`、`userData.decals[face]={source,assetId,fit,scale,ox,oy,rot}`；墙在 `room.decalFaces / room.decals`，键 `A` / `B`。没有可贴面时不写这两个字段。随方案快照，所以撤销、重做、自动保存、复制、导入导出都自动带上；`validateLayout` 用 `DecalModel.cleanDecals` 只保留该物件允许的面，坏的单张贴图丢弃。不升存储版本号。
- **图片**：IndexedDB 库 `ces-decal-assets`，键是存进去那份图片字节的 SHA-256；长边超过 2048 像素先缩小，SVG / WebP 转 PNG。先存图成功再写引用。导出 JSON 顶层加 `assets:{id:{mime,width,height,base64}}`，只含导出范围用到的；导入时先 `validateAssets` 校验、再写仓库、最后才追加方案。导入文件上限从 12MB 放到 150MB（图片会让文件变大）。
- **Figma**：浏览器直连 `GET api.figma.com/v1/images/:fileKey?ids=:nodeId&format=png`（请求头 `X-Figma-Token`），再下载返回的图片地址进仓库。令牌存 localStorage `ces-figma-token`，不进方案、导出、日志和下载的编辑器。**用真令牌取图未验证**（测试里用假接口）：若图片地址不允许网页读取，面板会报「跨域限制，这个做法走不通」，届时再定方案，不加本机中转。
- **渲染**：每张贴图是挂在物体组（墙则挂在墙体上）下的一块平面，`geometry()`、`buildRoom()` 重建时从数据重画；按面的实际尺寸画一张画布纹理（摆法、大小、偏移、旋转都在画布里算，不拉伸），sRGB、不受色调映射。面的位置尺寸在 `DecalModel.faceSpec / wallSpec`，离面 3 毫米。
- **接入 app.js 的点**：`geometry()` 末尾、`buildRoom()` 末尾画贴图；`restore()` 后刷新面板；`select()` 在贴图模式下不选中、选别的物体时结束选面；画布单击先交给 `decalUI.onCanvasClick`；步行、路线、放置会退出贴图模式；导出 / 导入带图片。
- **可贴范围（2026-11-14 用户追加，盖过确认版「不做圆桌 / L 型台 / 电视屏」）**：`DecalModel.facesFor(type, 物体数据)` 定义——前台 5 面；L 型台 6 个立面（`front/back/left/right/endA/endB`，台面是 L 形不做）；方形吊楣外侧 4 面（圆形是曲面，不做）；小圆桌 `top`（圆形平面，`faceSpec` 返回 `round:true`，用 CircleGeometry，纹理还是方画布）；电视、闺蜜机 `screen`；易拉宝、立牌 `front`。人、电脑、摄像头、椅子、机器人没有。点中哪个面不再靠法线猜，而是看点中的位置落在哪个面的范围里（L 台有两个面朝同一边）。
- **左栏「场地」区**（id `roomPanel`）只在什么都没选中时显示；选中物件或 Creator Space 时收起。
- **选面改到贴图模式里（2026-11-14 用户改，盖过确认版第 1 条「常规模式左栏选面 + 保存」）**：左栏不再有「可贴图的面 / 可贴图的墙面」。贴图模式提示条上「管理贴面」开关：开着时悬停任意物体 / 墙的可贴面高亮，单击立即加上或去掉（每次一步撤销）；去掉已贴图的面先弹带蒙层的确认窗（`.dk-modal`）。面板打开的那一面一直描蓝框（`markCurrent`，图不被盖住；没图时加浅蓝底），不再闪一下就消失。版本 v0.1.19。
- **验证**：`src/test-decal-model.cjs` 14 项、`src/test-decals-ui.cjs` 9 组全绿；原有定向测试（物品、放置、自动保存、指南针、默认方案、交付回归、路线各项）不退步。`test-venue` 的 `getMatrixAt` 报错、`test.cjs` 的墙长互换旋转断言，改动前的版本上同样失败。截图 tmp/decals/shots/。
