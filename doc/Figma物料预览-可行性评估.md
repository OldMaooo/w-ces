# Figma 物料设计稿 → 展台 3D 预览：可行性评估

日期：2026-11-13。状态：评估建议，未确认实施方案，未修改应用。

后续进展：下文是实图试验前的评估快照；真实台面 MVP 已验证且获用户认可，当前方案以 [应用内交互计划](plans/2026-11-13-Figma贴图交互-计划.md) 为准。

## 结论与推荐

可行。复用现有 Three.js 场景，增加 Figma Frame 图片来源和物料表面的贴图绑定。推荐首次粘贴链接、后续手动更新；先验证一面背景墙，再扩展前台、桌面牌和易拉宝。不需要 AI 识图，也不需要重建 Figma 图层。

核心流程：选物料与表面 → 粘贴 Frame 链接 → 授权读取 → 获取 Frame 元数据及 PNG → 保存图片副本 → 等比贴到指定表面 → 改稿后点击更新。

## 当前基线（本轮直接检查源码与项目文档）

- `src/app.js` 使用 Three.js；已有 CanvasTexture、平面屏幕贴图、物料尺寸、方案切换、撤销及 JSON 导入导出。
- 墙是 roomGroup 下命名为 wallA/wallB 的对象；前台和亚克力牌已有模型；易拉宝未定义。
- 目前没有通用图片贴图、Figma 授权、来源绑定或图片资产存储。
- 布局用 localStorage 和 JSON 保存，导入校验会剔除未声明字段，导入文件上限 12 MB。增加高清图片必须处理配额、资产去重、导出打包及旧方案兼容。
- 当前目录不是 Git 仓库；没有执行 Git 写操作。
- 文档记载已有静态公开站点，但本轮没有验证线上部署能力或行为。

## 官方能力与接入路径

1. REST API 的 `GET /v1/images/:key?ids=...&format=png` 可渲染指定 Frame 的完整设计；不要误用仅获取图片填充原图的 `/v1/files/:key/images`。从链接解析 fileKey/nodeId，正常化链接中的节点编号，并确认目标 Frame。
2. 读取需授权及 `file_content:read` 权限；链接分享权限不能代替 API 凭证。个人本地工具可使用个人令牌；供多人使用时推荐各自 OAuth 授权。
3. 建议本地试点用本机读取服务保管个人令牌；公开网页版本使用受保护的服务端代理与用户授权。不要把个人令牌写进公开 HTML、布局 JSON 或共享日志。公开接入不能只靠当前离线单页承担所有职责。
4. 现有 Codex Figma 连接器可协助研发期间读取，但不能视为用户打开普通网页时自动拥有的连接能力。
5. 官方支持插件内 `exportAsync` 导出 PNG，若账户配额无法支持频繁改稿，可评估 Figma 插件主动导出方案；这会改变“只贴链接”的操作路径，暂不作为首选。

## 物料映射规则（待实施前确认）

| 物料 | 建议绑定 | 主要注意点 |
| --- | --- | --- |
| 背景墙 | A/B 墙内侧各一张 Frame | 直接使用该墙尺寸，墙长变化后重新检查比例；不要铺到外侧 |
| 前台 | 正面、左右侧分别绑定 | 一个 Frame 对一个印刷面；完整展开稿需切面后使用 |
| 亚克力牌 | 插页或印刷面绑定 | 区分白底插纸和透明直印；第一版先支持白底插页 |
| 易拉宝 | 新增可调尺寸的平面及底座 | 按成品可视面比例，隐藏的收卷部分不纳入默认预览 |

- Figma 像素只决定宽高比例和清晰度，实际米/厘米由物料尺寸决定。例如 6100×2800 的 Frame 可对应 6.1×2.8 米墙面，不代表 6100 像素天然等于 6.1 米。
- 默认等比完整显示；比例不符提示用户，不能静默拉伸或裁掉文字。裁切与偏移如后续支持，应显式选择。
- 贴图跟随物体移动、旋转、隐藏、复制和尺寸重建，不应留在场景原位置。平面朝向、镜像、深度闪烁、旧纹理释放需验证。

## 更新与资产保存建议

- 绑定记录应包含物料/墙面标识、面标识、fileKey、nodeId、Frame 名称/比例、适配方式、资产标识、成功更新时间；凭证独立管理。
- 下载图片字节并保存本地资产，不能只保存 Figma 返回的临时地址。官方说明 Frame 渲染地址在 30 天后过期。
- 每份方案引用自己确认过的图片版本；复制方案可共享不可变资产，更新一份方案时生成新资产引用，避免旧方案一起变化。
- 获取或渲染失败保留上次成功图片，显示具体错误；429 按 Retry-After 提示和退避。同文件多个 Frame 可批量导出。
- 图片不建议原样大量塞进 localStorage；可用 IndexedDB 保存图片，导出为带图片的方案包。具体格式须与旧 JSON 导入兼容方案一起确认，不能本轮擅自变更。
- 3D 预览先用适量分辨率（例如长边约 2048 像素，真实上限通过设备测试确定）；不要按印刷分辨率把整面背景墙直接装进显存。

## 风险与未验证项

- API 限额取决于席位、文件所在计划及端点；低配额账户可能不适合反复更新。官方限额页面正文、表格和示例存在数字不一致，因此本评估不承诺固定次数；以实际账户响应为准。
- 尚无用户提供的真实 Frame，未验证授权、真实图片下载、浏览器跨域、3D 应用、性能、离线重开及导出迁移。
- 模型有灯光与色调映射，需选择适当贴图颜色设置；3D 效果用于空间、内容和可读性预览，不能作为印刷颜色、出血、刀模、透明材质工艺验收。
- 完整接入属于中等规模功能：贴图本身较轻，授权和带图方案保存的工作量更大。公开多人版本比个人本地版本多出持续维护和服务端部署成本。

## 建议验证顺序（未开始）

1. 用用户自己的一个背景墙 Frame 验证读取权限、实际限额与 PNG 导出；如不成立，先停在接入层。
2. 将该图贴到单面墙，核对正反、宽高、改尺寸以及撤销；先做可点原型供确认。
3. 验证 Figma 改稿后手动更新、失败保留旧图，以及方案副本不受更新影响。
4. 验证断网重开、带图导出和隔离浏览器导入，确认资产随方案走，再扩展其他物料。

下一项若用户决定推进：单 Frame 的接口可行性试验，建议 gpt-6.1-terra + medium；目标是尽早验证账户与图片获取，不先搭完整系统。正式实施前另写确认版计划并审定持久化规则。
