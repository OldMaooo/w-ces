# Figma 贴图交互

## 1. 已确认与基线

- 目标：选一个实体表面 → 粘贴 Figma Frame link → 获取图片并预览；可清空、旋转，同一面保存多个设计方案；复制该面尺寸到 Figma 创建等比例 Frame，换算倍率可设。
- 用户已认可单面实图 MVP；确认先在本台 Mac 使用，可随应用启动本机连接服务。
- 实图验证：fileKey `hkThqgj7sjrkV0aBRmHYEm` / node `1:3`，PNG 810×300 → desk #12 正面 2.7×1 m，方向、比例、离线展示通过。证据见 [MVP记录](../Figma台面贴图-MVP验证.md)。连接器读取成功不代表应用 REST 授权已打通。
- 实际 JSON 场地 6.1×5.5 m；用户口头曾说长墙 6.7 m。此功能始终读方案尺寸，不擅改场地。
- 当前是 Three.js 离线单页；源码 `src/app.js`、`src/editor.html`，`src/build.py` 内嵌生成 `index.html`。布局 localStorage + v2 JSON，导入上限 12 MB，校验器会丢弃未知字段。当前目录无 Git 仓库。
- 下述交互和数据细则均为推荐草案，不能当作已实现或用户逐项确认。

## 2. 交互契约

主路径：`进入贴图模式 → 点面 → 复制尺寸模板 → Figma 设计 → 复制 Frame link → 返回粘贴 → 应用 → 对比设计方案`。已有设计可跳过建稿步骤。

| 动作 | 推荐行为 |
|---|---|
| 进入/退出 | 工具栏「贴图」开关；进入后停用物体移动/旋转手柄，保留视角拖动和缩放；Esc 退出。步行模式与贴图模式互斥。 |
| 选择面 | 悬停只描边可贴面，单击锁定；侧栏显示物料名、面名、实际宽×高、「正对该面」。拖动镜头不触发选面；侧栏面列表可选被遮挡的面。 |
| 粘贴链接 | 输入完整 Frame link，Enter/「应用」获取；显示加载/错误。首次成功新增并激活设计；「添加设计」用于新链接；同面重复链接定位已有设计。普通文件链接缺 node-id 时提示复制具体 Frame 链接。 |
| 多个设计 | 每面独立缩略图列表，一次只显示一个；点卡片立即切换，不再次联网。卡片可改名、更新原稿、打开 Figma、删除。不是多张图叠加，也不是整个展台布局方案。 |
| 清空/删除 | 「清空贴图」令当前面无激活设计、恢复原材质，保留候选设计；「删除设计」才移除候选。删除正在显示的设计后恢复原材质，不自动换另一张；均可撤销。 |
| 方向 | 左/右旋转每次 90°；水平/垂直镜像与「重置方向」放次级操作。只改当前设计，其他候选保持各自方向。旋转后重新计算适配，禁止拉伸图文。 |
| 比例 | 默认等比完整显示、居中；不一致时留出原底色并提示推荐 Frame 尺寸。首版不提供自由裁切/偏移/拉伸；换面或改物料尺寸后重算。 |
| 改稿 | Figma 编辑后手动「更新原稿」；成功替换此候选图片，保留方向；失败继续显示旧图。复制了新 Frame 产生新 node-id 时，用「更换链接」显式重绑。 |
| 尺寸 | 显示物理尺寸与换算尺寸，例如 `2700×1000 mm → 810×300 px`；复制宽/高文字可作兜底，主要目标是「复制 Figma 尺寸模板」。 |

首版支持：A/B 墙内侧、矩形前台正/背/左/右/顶面、亚克力牌正反插页面。所有可贴面必须显式登记；圆桌、曲面吊楣、L 型不规则台面、任意网格先不开放。后续增加易拉宝时复用矩形面能力，不在本轮新建其物料模型。

## 3. 尺寸 → Figma（先验证的技术门槛）

- 设置只用明确单位：`1 米 = S Figma px`，推荐默认 `S=300`；`Wpx=round(Wm×S)`、`Hpx=round(Hm×S)`，四舍五入到整数、最小 1 px。S 必须为有限正数；过大尺寸应提示调整，禁止暗中缩小。
- S 是本机编辑器偏好，不是物理比例/DPI，也不写进布局 JSON；改变 S 只影响今后创建的模板，不修改已有 Frame、模型或贴图。尺寸展示与复制必须共用同一计算结果。
- 目标验收：应用点击复制 → Figma 画布粘贴 → 得到可编辑、宽高准确的原生 Frame；名称建议 `前台12·正面·2700×1000mm`。不得用粘贴尺寸文字冒充完成。
- 优先试无插件的 SVG 剪贴板模板：显式 width/height/viewBox、无描边且完整覆盖边界的矩形。官方确认可粘贴外部 SVG，**尚未证明本模板粘贴后的节点类型、尺寸、名称符合目标**。实际 Figma 检查这些属性后才能把按钮称为「复制 Frame」。空 SVG 被丢弃、缩放、仅生成矢量组均算失败。
- 若 SVG 只能生成等尺寸矢量对象，可提议用户再转为 Frame；若必须一次粘贴得到原生 Frame，则提议轻量 Figma 插件读取尺寸描述并执行 `createFrame().resize(W,H)`。这会多一个插件步骤，须先澄清接受哪条路。不要预先实现插件或依赖未公开的 Figma 原生剪贴板协议。
- 本轮只做文档核实；复制/粘贴实测必须在下一轮授权后进行，不改用户现有稿件。

## 4. 实现与数据不变量（建议，实施前确认）

**面绑定**：以 `(planId, ownerKey, surfaceId)` 标识；ownerKey 为 `wall:A/B` 或方案内 `object:<id>`。surfaceId 使用语义名，禁止使用 child 数组位置、运行时 mesh UUID 或三角形 faceIndex 作为持久 ID。每个 Surface 描述局部原点、朝外法线、读图向右/向上轴、可视宽高及原装饰处理。

**尺寸来源**：使用真实可印刷面，不直接拿对象包围盒。墙 A=depth×2.8、B=width×2.8，B 模型多出的 0.12 m 厚度接头不算设计宽度；desk 正背=w×h、侧=d×h、顶=w×d；现有 acrylic 插页面=.82w×.76h，须与模型白纸范围一致。顶面定义固定阅读方向并显示方向标记。

**建议状态**：`layout.surfaceDesigns[ownerKey][surfaceId]={activeId:null|string, designs:[{id,name,source:{url,fileKey,nodeId},assetId,frame:{name,width,height},rotation:0|90|180|270,flipX,flipY,updatedAt}]}`。每个设计独立变换；同源不同面可共享图片字节，不共享可变配置。图片资产以内容 hash 去重、不可变。

**渲染**：从 MVP 复用局部面贴图与 sRGB 配置；取 Frame 的逻辑矩形，导出限制在该矩形内，避免外溢阴影影响比例。方向变换先镜像再按面对图像时顺时针旋转，然后等比适配。贴图覆盖时隐藏该面的占位装饰，清空时恢复；深度偏移不参与物体吸墙/包围盒计算。移动/旋转/隐藏跟随物体，geometry/buildRoom 重建后从数据恢复。共享资产的 GPU 纹理须有引用生命周期，避免当前 release() 误销毁其他面的贴图。

**读取**：本机服务同时提供固定 localhost 来源的应用和 Figma REST 代理；首次配置用户本人只读凭证，保存在本机受保护存储，不进 HTML、JSON、浏览器持久化或日志。仅监听 loopback、校验 Origin/Host 和会话，接口只接受解析后的 fileKey/nodeId，不提供任意 URL 代理。公开部署/OAuth 不在首版。

**请求**：解析允许的 Figma design/file 链接、正规化 node-id；读取元数据并确认 Frame，调用 `/v1/images/:key` 导出 PNG，下载字节，返回元数据和图片。预览长边目标约 2048 px，按 GPU 能力限制；设计倍率 S 不决定渲染分辨率。拒绝空图/超限/损坏图；429 按 Retry-After 处理。每次请求携带方案/面/设计与修订标识，切面、切方案、删除或撤销后迟到响应不得覆盖新状态。

**本机保存**：建议资产 Blob 放 IndexedDB，布局仍 localStorage；先写入资产成功，再保存引用，不能提前显示“已保存”。保留已有多窗口覆盖保护。撤销/重做、方案/物料复制、导入追加必须包含面绑定；复制布局复用不可变资产，更新副本不能改变原方案。资产回收需保留所有方案及撤销/重做引用，首版不做激进回收。

**带图导出**：建议继续单个 JSON，升级 v3，文件级 `assets:{assetId:{mime,width,height,base64}}` 去重，包含导出范围内全部候选而非仅激活设计；不含凭证/临时图片 URL。兼容读 v2/旧 HTML；旧编辑器不能读 v3，需明确提示。扩展 parseWorkspace/validateLayout，导入先完整验证图片/引用/大小再追加，失败不污染现有方案。原 12 MB 限制需按代表性带图方案重新定预算并在导出前预检，不静默丢图。下载编辑器仍不携带用户设计。

**离线**：已获取图片可离线预览、切换、旋转和导出；获取/更新需要联网及本机服务。下载 HTML 可导入带图 JSON 离线查看，file:// 剪贴板和自动保存差异须实测，不承诺与 localhost 完全一致。

## 5. 通信基础设施（用户追加：要求评估，仍未实施）

判断：需要一个薄的本机连接层，提前稳定接口、身份、失败恢复和数据归属；不需要建设通用同步平台。

链路：`应用 → 同源 /api/v1 → 本机 Figma 适配器 → Figma 官方 REST`；返回 `Frame 元数据 + PNG 字节 → 应用资产库 → 指定面`。应用层不依赖 Figma 返回结构，也不依赖 Codex/MCP 会话。未来插件接入只替换适配器，不重写面绑定/资产/多设计逻辑。

最小接口契约（建议）：

| 接口 | 职责 |
|---|---|
| `GET /api/v1/status` | 返回服务版本、能力及凭证是否配置；区分本机服务可用与 Figma 授权已实际验证，不以“服务在线”冒充连接成功。 |
| `POST /api/v1/connection/test` | 用给定 Frame 验证凭证、文件访问及导出能力；不更改布局。 |
| `POST /api/v1/figma/render` | 输入 fileKey/nodeId、目标像素和刷新标记；返回 requestId、Frame 名称/逻辑尺寸、可取得的源版本、assetId、图片尺寸、取得时间和临时本机下载路径。 |
| `GET /api/v1/assets/:assetId` | 获取本次生成的已验证 PNG；应用写入自身资产库后才提交面绑定。服务缓存只是可丢弃的中间副本，不是方案唯一存档。 |

- 凭证采用个人 PAT（`file_content:read`），首次配置通过本机引导写入 macOS Keychain；支持替换/断开。凭证永不回传客户端；状态页仅显示连接状态。首次建立与到期后仍需用户授权，不能宣称零配置。
- 服务与页面一键启动、固定 origin（scheme/host/port）以保留现有浏览器存储；重复启动复用已验证实例，端口冲突明确提示，不随机换端口造成“方案消失”。新增能力必须有服务版本/能力检测。
- 首版用普通 HTTP 请求；并发上限 2，同源同参数在途请求合并。临时失败有限重试（最多 2 次），鉴权/权限/无节点不自动重试；429 按 Retry-After 返回可重试时间。单请求设置超时，失败保留旧设计，不无限等待。
- 统一错误码：`AUTH_REQUIRED / ACCESS_DENIED / NODE_NOT_FOUND / RATE_LIMITED / OFFLINE / TIMEOUT / RENDER_FAILED`；前端翻译成人话。日志仅记录 requestId、阶段、耗时、结果，不记录凭证、图片或完整私有链接。
- 缓存键包含来源、可取得的源版本和导出参数；手动刷新必须检查最新内容，不能永远命中旧图。设计切换直接使用本机快照，不触发网络；“已取得时间”与“已确认最新”分开表达。
- 元数据与导出尽量使用同一源版本；如接口不能保证，则检测更新过程中的版本变化并重取/提示，不能把旧尺寸配新图。返回结果经应用修订校验后才能提交（见 §4）。
- 数据主人：设计内容在 Figma；面尺寸、候选列表、方向和激活状态在应用；本机服务只负责连接。应用旋转贴图不回写 Figma；模型改尺寸不擅改原稿。
- 反向“应用 → Figma 建 Frame”独立为 `FrameSpec v1={name,widthPx,heightPx,physicalWidthM,physicalHeightM,pxPerMeter}`，由同一尺寸计算生成。首版走剪贴板验证；确需插件时复用此描述，不能认为 REST 图片读取接口也能创建 Frame。
- 暂缓 WebSocket、Webhooks、后台持续轮询、自动双向覆盖和公开云服务。只有用户实际需要改稿即时预览，且手动更新成为瓶颈时，再验证插件推送；不得假设插件关闭后仍可常驻通信。

基础设施通过条件：独立于 Codex 可启动/读取；首次配置与凭证失效可恢复；服务重启后原方案仍在；断网旧图可看；重复刷新不产生乱序覆盖；错误可定位到具体阶段；导出的方案不依赖服务缓存。

依据：Figma 官方 [授权说明](https://developers.figma.com/docs/rest-api/authentication/) 推荐个人本地工具用 PAT；[文件接口](https://developers.figma.com/docs/rest-api/file-endpoints/) 提供节点信息与图片导出。其余为本项目架构建议，尚未联调验证。
